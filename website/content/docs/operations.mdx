## Sink health

- **Healthy**: newest observed delivery succeeded.
- **Degraded**: newest delivery failed after earlier successes.
- **Failing**: at least three recent deliveries failed.
- **Paused**: sink is disabled.
- **Unknown**: no delivery attempt yet.

Walflow keeps 100 delivery records per sink and displays the newest 20. Entries include event ID, time, outcome, optional HTTP status, and a redacted error. They never include payloads or secrets.

## Logs

```powershell
docker compose ps
docker compose logs -f walflow-server
docker compose logs -f redis
```

Look for `webhook delivered` or `webhook delivery failed`. Confirm the sink is enabled, connected to the same pipeline as the changed table, and that the receiver returns a 2xx response.

## Update, backup, and uninstall

Set `WALFLOW_IMAGE` in `.env` to a newer supplied image, then run:

```powershell
docker compose pull
docker compose up -d
```

Do not use `-v` when updating. To stop while preserving data, run `docker compose down`. `docker compose down -v` permanently removes saved configuration, history, and buffered events.

Back up the `walflow-data` and `walflow-redis-data` volumes after `docker compose down`, and preserve `APP_ENCRYPTION_KEY` with the metadata backup. The Docker Compose package README contains the exact backup and restore commands.
